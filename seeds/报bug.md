把下面描述的问题整理成一份可复现的 bug 报告，按此结构：

1. **现象**：一句话说清什么坏了（用户视角，不猜原因）。
2. **影响与严重度**：影响哪些用户 / 功能 / 平台；严重度三选一：阻断（不能用）/ 可用性降低（部分可用）/ 体验问题。拿不准写「待确认」，不要抬级。
3. **环境**：OS / 运行时及版本 / 相关依赖版本（缺什么就标「待确认」，不要编造）。
4. **复现步骤**：编号步骤，每步可独立执行；能脚本化的一行命令优先。步骤必须从我给的信息里推出，缺的信息列出来，不要编造。
5. **期望 vs 实际**：各一行。
6. **最小复现**：若能从给定信息推出，给出最小复现代码/命令；推不出则列出还缺哪几项信息。
7. **已排除**：区分「我验证过不是」与「我猜不是」两类，分别列出。
