根据当前分支相对 base 的改动（git diff base...HEAD）写 PR 描述：

1. 摘要：一句话说清解决什么问题，≤50 字。
2. 改动内容：按模块列 2-5 条要点，不是逐文件复述。
3. 为什么这么做：关键取舍与备选，一段话。
4. 怎么验证：可执行的步骤或命令，reviewer 能照做。
5. 风险与回滚：影响面、是否需要开关、回滚方式。
6. 关联：Closes #N / 依赖的 PR。
只输出 PR 描述本身，不要客套话和总结段。
