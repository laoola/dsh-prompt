帮定位性能问题：
现象：[慢在哪：接口 / 页面 / 任务 / 数据库]
现状指标：[P50 / P95 / 吞吐 / 内存 / CPU，有就贴数字]
环境：[数据量级 / 并发 / 部署形态]

要求：
1. 先定量：把问题换算成可测指标（目标 P95 多少、当前多少），没有基线先测基线。
2. 列瓶颈假设清单，按可能性排序，每条标明属于哪层：应用逻辑 / 锁与并发 / GC 与内存 / IO 与网络 / 数据库 / 外部依赖。
3. 每个假设给测量方法（用什么工具、看什么指标、怎么判定成立或证伪），从成本最低的开始。
4. 不要直接给「加缓存 / 上索引」的套话，结论必须建立在已测数据上。
5. 给修复方案时同时给回归基线：修完怎么验证、防复发看哪个指标。
